## Steps
### Step 1 — Safety net: characterization tests
**Why**: No tests exist, and step 2 is RISKY. These tests assert what the code does today, quirks included (an empty `name` produces "Hi , thanks for joining!"; the email is not trimmed).
**Change**: new file tests/test_registration_characterization.py
```python
import hashlib
import unittest
from unittest import mock

from accounts import registration as reg

VALID = {'email': 'a@b.io', 'password': 'Passw0rd'}


class RegisterUserCharacterization(unittest.TestCase):
    """Pins current behavior, quirks included. Written before refactoring; must pass before and after."""

    def setUp(self):
        self.db = mock.Mock()
        self.db.find_one.return_value = None
        for name, value in [('db', self.db), ('send_email', mock.Mock()),
                            ('log', mock.Mock()), ('datetime', mock.Mock())]:
            patcher = mock.patch.object(reg, name, value)
            patcher.start()
            self.addCleanup(patcher.stop)
        reg.datetime.now.return_value = 'NOW'

    def test_validation_messages_in_order(self):
        cases = [
            ({}, 'Email required'),
            ({'email': 'no-at.io'}, 'Invalid email'),
            ({'email': 'a@nodot'}, 'Invalid email'),
            ({'email': 'a@b.io'}, 'Password required'),
            ({'email': 'a@b.io', 'password': 'Sh0rt'}, 'Password too short'),
            ({'email': 'a@b.io', 'password': 'alllower1'}, 'Password needs uppercase'),
            ({'email': 'a@b.io', 'password': 'NoDigits'}, 'Password needs digit'),
        ]
        for data, message in cases:
            with self.subTest(data=data):
                self.assertEqual(reg.register_user(data), (False, message))
        self.db.find_one.assert_not_called()

    def test_duplicate_email_has_no_side_effects(self):
        self.db.find_one.return_value = {'email': 'a@b.io'}
        self.assertEqual(reg.register_user(VALID), (False, 'Email already registered'))
        self.db.insert.assert_not_called()
        reg.send_email.assert_not_called()

    def test_success_side_effects(self):
        self.assertEqual(reg.register_user({**VALID, 'name': ''}), (True, 'Registration successful'))
        self.db.insert.assert_called_once_with({
            'email': 'a@b.io',
            'password': hashlib.md5(b'Passw0rd').hexdigest(),
            'name': '',
            'created_at': 'NOW',
        })
        self.assertEqual(reg.send_email.call_args_list, [
            mock.call('a@b.io', 'Welcome!', 'Hi , thanks for joining!'),  # quirk: '' is not replaced by 'there'
            mock.call('admin@company.com', 'New user', 'New user registered: a@b.io'),
        ])
        reg.log.info.assert_called_once_with('User registered: a@b.io')

    def test_email_is_not_trimmed(self):
        reg.register_user({**VALID, 'email': ' a@b.io '})
        self.db.find_one.assert_called_once_with({'email': ' a@b.io '})

    def test_non_string_email_raises(self):
        with self.assertRaises(TypeError):
            reg.register_user({**VALID, 'email': 12345})


if __name__ == '__main__':
    unittest.main()
```
**Verified by**: `python -m unittest tests.test_registration_characterization` on the original code → `Ran 5 tests … OK`.

    if not any(c.isdigit() for c in data['password']):

### Step 3 — Introduce local variables: `email`, `password`
**Why**: Removes the repeated `data['email']` / `data['password']` lookups (smell 2) in both functions.
**Change**: `_registration_error` after the step:
```python
def _registration_error(data):
    """Return the first validation error message for a registration payload, or None if it is valid."""
    email = data.get('email')
    if not email:
        return "Email required"
    if '@' not in email or '.' not in email.split('@')[1]:
        return "Invalid email"
    password = data.get('password')
    if not password:
        return "Password required"
    if len(password) < 8:
        return "Password too short"
    if not any(c.isupper() for c in password):
        return "Password needs uppercase"
    if not any(c.isdigit() for c in password):
        return "Password needs digit"
    return None
```
`email`/`password` hold the same object that `data['email']`/`data['password']` returned, because `data` is a dict. `register_user` after the step (`data['password']` on the MD5 line stays, since that line is not touched):
```python
def register_user(data):
    error = _registration_error(data)
    if error is not None:
        return False, error
    email = data['email']
    existing = db.find_one({'email': email})
    if existing:
        return False, "Email already registered"
    hashed = hashlib.md5(data['password'].encode()).hexdigest()
    user = {
        'email': email,
        'password': hashed,
        'name': data.get('name', ''),
        'created_at': datetime.now()
    }
    db.insert(user)
    send_email(email, 'Welcome!', f"Hi {data.get('name', 'there')}, thanks for joining!")
    send_email('admin@company.com', 'New user', f"New user registered: {email}")
    log.info(f"User registered: {email}")
    return True, "Registration successful"
```

## Deliberately not changed
- The two `send_email` calls and `log.info` (lines 31-33): 3 lines, used once. Extracting a `_notify` helper adds a jump without a new contract.
- `db.find_one` stays next to its only caller.
- Password rules stay as plain `if`s. A rule table would be an abstraction with a single consumer.
- `datetime.now()` (naive local time): switching to UTC would change the stored value.
- The f-string in `log.info`: switching to `log.info("…%s", email)` changes the log record's `msg`, which handlers and tests can observe. Do it as its own lint change if the project wants it.
- `'admin@company.com'` is used once and is self-explanatory, so it gets no constant.

## Behavior changes recommended (not applied)
### 🔴 BLOCKER Passwords are stored as unsalted MD5
**Location**: accounts/registration.py:23 (after refactor: line 15)
**Problem**: Unsalted MD5 is fast to brute-force, and identical passwords produce identical hashes. A database leak exposes most passwords.
**Proposed change**: Hash with bcrypt or argon2 via a vetted library, in its own change reviewed as a security fix. This is DANGEROUS work: confirm the approach with the user first.
**Migration / rollout**: Existing rows hold MD5 hex, and the login/verify code (not in this file) is assumed to compare MD5, so write and verify must change together. (1) Store the algorithm with each hash, and deploy verify code that accepts both formats before any new-format hash is written. (2) Hash new registrations with the new algorithm. (3) On each successful login, re-hash MD5 rows. (4) To protect dormant accounts now, wrap the existing MD5 hex in the new algorithm (`bcrypt(md5_hex)`, marked as its own format) in a batched backfill. Old-format rows then remain only until the backfill finishes. Add tests for both formats.

### 🟠 MAJOR Duplicate-email check is racy
**Location**: accounts/registration.py:20-30
**Problem**: `find_one` and then `insert` is check-then-act. Two concurrent registrations for the same email can both pass the check and both insert.
**Proposed change**: A unique constraint on `email` in the store (assuming the store supports one), with the duplicate-key error mapped to the existing "Email already registered" response.
**Migration / rollout**: Find and resolve existing duplicate emails before creating the constraint, or index creation fails.

### 🟡 MINOR Emails are not normalized
**Location**: accounts/registration.py:10, 20
**Problem**: `' a@b.io '` and `'A@b.io'` pass validation and are looked up and stored exactly as given, so they can become accounts separate from `'a@b.io'` (the characterization test pins the untrimmed lookup).
**Proposed change**: Trim and lowercase the email before validation and lookup.
**Migration / rollout**: Existing stored emails need the same normalization. Check for collisions it creates first, and apply the same normalization at login.

### 💭 NIT Empty name gives "Hi , thanks for joining!"
**Location**: accounts/registration.py:31
**Problem**: `data.get('name', 'there')` falls back only when `name` is missing, not when it is `''`.
**Proposed change**: `data.get('name') or 'there'`. This changes the email text, so update the characterization test in the same change.
**Migration / rollout**: none

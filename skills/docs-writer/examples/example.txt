# Example: /docs-writer

## User Input

Write API docs for our new file upload endpoint. Readers are frontend engineers
calling it from the browser. Production base URL is https://api.example.com.
Locally, `npm run dev` serves the API on http://localhost:3000 with S3 replaced
by a local stub, and accepts the token `dev-token`. src/storage/s3.js (not
pasted) uploads the buffer to S3 and returns the object URL.

```js
// src/routes/files.js
const crypto = require('node:crypto');
const express = require('express');
const multer = require('multer');
const { requireAuth } = require('../middleware/auth');
const { putObject } = require('../storage/s3');

const MAX_BYTES = 10 * 1024 * 1024;
const ALLOWED_TYPES = ['image/png', 'image/jpeg', 'application/pdf'];
const upload = multer({ storage: multer.memoryStorage(), limits: { fileSize: MAX_BYTES } });

const router = express.Router();

router.post('/v1/files', requireAuth, (req, res, next) => {
  upload.single('file')(req, res, async (err) => {
    if (err && err.code === 'LIMIT_FILE_SIZE') {
      return res.status(413).json({ error: { code: 'FILE_TOO_LARGE', message: 'File exceeds 10 MB' } });
    }
    if (err) return next(err);
    if (!req.file) {
      return res.status(400).json({ error: { code: 'NO_FILE', message: 'Form field "file" is required' } });
    }
    if (!ALLOWED_TYPES.includes(req.file.mimetype)) {
      return res.status(415).json({ error: { code: 'UNSUPPORTED_TYPE', message: `Type ${req.file.mimetype} is not allowed` } });
    }
    try {
      const id = `file_${crypto.randomUUID()}`;
      const url = await putObject(id, req.file.buffer, req.file.mimetype);
      res.status(201).json({
        data: { id, url, filename: req.file.originalname, size: req.file.size, mime_type: req.file.mimetype },
      });
    } catch (e) {
      next(e);
    }
  });
});

module.exports = router;
```

```js
// src/middleware/auth.js
const { verifyToken } = require('../auth/tokens');

function requireAuth(req, res, next) {
  const header = req.headers.authorization || '';
  const token = header.startsWith('Bearer ') ? header.slice(7) : null;
  if (!token || !verifyToken(token)) {
    return res.status(401).json({ error: { code: 'UNAUTHORIZED', message: 'Missing or invalid token' } });
  }
  next();
}

module.exports = { requireAuth };
```

Upload one PNG, JPEG, or PDF file (up to 10 MiB) and get back its ID and storage URL. For frontend engineers calling the API from the browser.

## Authentication
Send a bearer token in the `Authorization` header: `Authorization: Bearer <TOKEN>`. A missing header, a header without the `Bearer ` prefix, or a token that fails verification returns `401 UNAUTHORIZED`. Authentication is checked before the file is read.

## POST /v1/files
Upload a single file as `multipart/form-data`.

### Parameters
| Name | In | Type | Required | Constraints |
|---|---|---|---|---|
| `Authorization` | header | string | Yes | `Bearer <TOKEN>` |
| `file` | multipart form field | file | Yes | At most 10,485,760 bytes (10 MiB). The part's `Content-Type` must be `image/png`, `image/jpeg`, or `application/pdf`. |

The type check reads the `Content-Type` the client declares for the part. The server does not inspect the file content. curl derives that type from the file extension. Browsers use `File.type`.

### Request example
curl:

```bash
curl -X POST "$API_BASE/v1/files" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@photo.png"
```

Browser (`fetch`):

```javascript
const API_BASE = 'http://localhost:3000';

async function uploadFile(file, token) {
  const body = new FormData();
  body.append('file', file); // a File from <input type="file">
  const res = await fetch(`${API_BASE}/v1/files`, {
    method: 'POST',
    // Do not set Content-Type yourself: fetch adds the multipart boundary.
    headers: { Authorization: `Bearer ${token}` },
    body,
  });
  const json = await res.json().catch(() => null); // undocumented errors may not be JSON
  if (!res.ok) {
    throw new Error(json?.error ? `${res.status} ${json.error.code}: ${json.error.message}` : `HTTP ${res.status}`);
  }
  return json.data;
}
```

### Errors
All errors below return `{ "error": { "code": "...", "message": "..." } }`. Checks run in this order: authentication, then size, then presence, then type.

| Status | Code | Cause | Fix |
|---|---|---|---|
| 401 | `UNAUTHORIZED` | Missing, malformed, or invalid bearer token | Send `Authorization: Bearer <TOKEN>` with a valid token |
| 413 | `FILE_TOO_LARGE` | File is larger than 10,485,760 bytes | Upload a file of at most 10 MiB |
| 400 | `NO_FILE` | Multipart body with no file part (only text fields), or a body that is not multipart (for example JSON) | Send `multipart/form-data` with the file in a field named `file` |
| 415 | `UNSUPPORTED_TYPE` | Declared part type is not `image/png`, `image/jpeg`, or `application/pdf` | Send an allowed type (see Troubleshooting for files with no extension) |

Other failures go to the app's global error handler, and their status and body are not documented here: a file sent under a different field name, a malformed multipart body, or a storage error. [TODO: confirm global error handler behavior]

## Troubleshooting
**`415 UNSUPPORTED_TYPE` with message `Type application/octet-stream is not allowed`** — The client could not determine a type, for example because the file has no extension or an unusual one. With curl, set the type explicitly: `-F "file=@scan;type=application/pdf"`. In the browser, check `file.type` before uploading and show the user an error when it is empty or not allowed.

**`400 NO_FILE` even though a file was attached** — The file was sent as JSON or base64 instead of multipart. Use `FormData` and `body.append('file', file)`.

**`fetch` upload fails but the same file works with curl** — A manually set `Content-Type: multipart/form-data` header has no boundary, so the body cannot be parsed (the multipart parser raises "Multipart: Boundary not found", which goes to the global error handler). Remove the header and let `fetch` set it.

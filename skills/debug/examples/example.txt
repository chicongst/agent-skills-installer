# Debug Report: test_regular_invoice fails in CI, passes locally

## Symptom
- **Expected**: `build_invoice([{"price": 50, "qty": 2}])` returns total `100.0`
- **Actual**: `AssertionError: 90.0 != 100.0` at test_billing.py:13
- **Frequency**: fails in CI (user report; run count not given); fails on 3 of 3 local runs of CI's command (see Reproduction)
- **Environment**: fails in CI (whole module); passes locally (single test by name)

removes one of those variables. Running CI's exact command locally:

## Root Cause
**Cause**: `build_invoice` uses a mutable default argument; Python evaluates `discounts=[]` once, at function definition, so every call that omits `discounts` shares one list.
**Where**: billing.py:1 (the list is mutated at billing.py:4)
**Causal chain**: test_promo_applied calls `build_invoice` with a promo → line 4 appends `0.1` to the shared default list → test_regular_invoice calls `build_invoice` without `discounts` → gets the same list `[0.1]` → lines 7-8 subtract 10% → total `90.0` → assertion at test_billing.py:13 fails.
Explains every observation: CI runs the whole module and unittest orders test methods by name, so `test_promo_applied` runs before `test_regular_invoice`; locally only the single test ran, so the default list was still empty. The wrong value is exactly the leaked 10% promo.
**Confidence**: Proven — the failure turns on with promo → regular order and off with the reverse order or a single test (H3), and the leaked value is observed directly (H5).

## Fix
```python
def build_invoice(items, discounts=None):
    if discounts is None:
        discounts = []
    for item in items:
        ...
```
**Why it works**: A new list is created on every call that omits `discounts`, so no state carries over between calls.
**Risk / behavior change**: None for callers that omit `discounts`, except that the leak is gone. Callers that pass their own list still have it appended to, as before — that is existing behavior and is left unchanged here; changing it would be a separate behavior change.

Regression test (added to BillingTest; order-independent because it makes both calls itself):
```python
    def test_promo_does_not_leak_into_next_invoice(self):
        build_invoice([{"price": 50, "qty": 2, "promo": 0.1}])
        inv = build_invoice([{"price": 50, "qty": 2}])
        self.assertEqual(inv["discounts"], [])
        self.assertEqual(inv["total"], 100.0)
```
